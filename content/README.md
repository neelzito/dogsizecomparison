# Site content

Everything outside the comparison tool is generated by `node tools/build_site.js`.
Run it after changing breed data (`js/breeds.js`) or anything in this folder.
The output folders (`breeds/`, `compare/`, `sizes/`, `groups/`, `origins/`,
`articles/`, `calculators/`, `about/`, `suggest-a-breed/`) are wiped and rewritten on every run, so
don't edit the generated HTML by hand.

The build also renders a social preview image (1200×630, `og:image`) for every breed
and comparison page into `img/og/`, using `tools/build_og.py`. Only changed images are
re-rendered (`img/og/manifest.json`). It needs Pillow in a local virtualenv, set up once:

    python3 -m venv .venv && .venv/bin/pip install -r tools/requirements.txt

Without it the build still runs but prints a warning, and images for new or changed pages are missing until you set it up.

- `articles/<slug>.md` → `/articles/<slug>/`. Front matter: `title` (the `<title>`),
  `h1`, `description`, `lede`, optional `date`. Body is simple Markdown (`##` headings,
  paragraphs, lists, tables, `> note`, links). A line `{{name}}` inserts a generated
  block; see `contentBlocks()` in `tools/build_site.js` for the list.
- `breeds/<breed-id>.md` (optional) → adds an "About the <breed>" section to that
  breed's page. The id is the URL slug, e.g. `breeds/beagle.md`. Use it for real,
  hand-written text: temperament, history, care. That is what makes breed pages
  stand out from data-only pages.
- `about.md` → `/about/`.
- `airlines.json` → airline cabin table, the airline calculator and the flying guide.
  Update `reviewed` whenever you check the rules again.

Ranked lists (smallest, tallest, heaviest, longest-living) are written in
`rankedArticles()` in `tools/build_site.js`. Comparison pairs live in
`tools/site/content-data.js`; every breed also gets a pair with its closest
same-group neighbour automatically.

## Adding a breed

1. Add a row to `BREED_ROWS` and its source to `BREED_SOURCES` in `js/breeds.js`.
   Other names people search for go in `BREED_ALIASES` (shown on the breed page and
   matched by every search box).
2. Add a drawing hint to `tools/hints.json`, then run
   `python3 tools/gen_all.py --only "Breed Name"` (Replicate, about $0.03 per image)
   and `.venv/bin/python tools/process_images.py <breed-id>`.
3. Run `node tools/build_site.js`.

Breed suggestions from `/suggest-a-breed/` arrive as GitHub issues titled
"Breed suggestion: …".

## Breed photos (Wikimedia Commons)

Each breed page shows a real photo from Wikimedia Commons with the credit the licence requires (photographer, licence, link to the Commons page).

- `tools/fetch_photos.py` takes the lead image of the breed's English Wikipedia article, accepts only free licences (CC0, public domain, CC BY, CC BY-SA, GFDL, GPL, FAL), and writes `img/photos/<id>.webp` plus the credit in `content/photos.json`.
- Run it with the project venv: `.venv/bin/python tools/fetch_photos.py <breed-id> ...`, `--all` for every breed without a photo, `--force` to refetch. It paces itself to stay under Wikimedia's rate limits.
- `tools/photo_overrides.json` picks a specific `"File:..."`, a different article (`{"title": "..."}`), or `null` for no photo. Use it when the lead image is wrong (another article, a collage, a shared photo for size variants).
- After adding a new breed: run the script for its id, look at the photo, then `node tools/build_site.js`.

## Breed traits (breed finder)

`content/traits.json` rates every breed 1–3 for `[energy, shedding, grooming, good with children, suits first-time owners, suits apartments]`. The ratings feed the "at a glance" card on breed pages and the filters on `/breed-finder/`. The build fails if a breed has no entry, so add one whenever you add a breed. In the finder, the checkboxes keep only the best rating: shedding or grooming 1, or children, first-time owners or apartments 3.

## Analytics

`content/site.json` turns on a cookie-free analytics script on every page:

```json
{ "analytics": { "provider": "cloudflare", "id": "<site token>" } }
```

`provider` is `cloudflare` (Cloudflare Web Analytics token), `goatcounter` (your GoatCounter code, e.g. `dogsize` for dogsize.goatcounter.com) or `plausible` (the domain, `dogsizecomparison.com`). Leave either field empty to turn analytics off. Rebuild after changing it.

## Photo thumbnails

Breed cards use 160 × 120 crops in `img/photos/thumb/`. `tools/fetch_photos.py` makes one for every photo it fetches; run `.venv/bin/python tools/fetch_photos.py --thumbs` to rebuild them all.

## German version (/de/)

`node tools/build_site.js` also builds every page in German under `/de/`, plus the German comparison tool at `/de/` (from `index.html`). English and German pages link to each other (hreflang tags and the EN/DE switch in the top bar).

- **Breed names:** `tools/site/de/names.js` holds the German name and grammatical gender of every breed. A `~` marks an adjective whose ending changes ("Deutsch~ Schäferhund" → "der Deutsche Schäferhund"). The build fails if a breed has no German name, so add one whenever you add a breed.
- **Generated sentences, groups, sizes and countries:** `tools/site/de/build.js` and `tools/site/de/lang.js`. They're written in German directly rather than translated from the English templates.
- **Hand-written text:** `content/de/breeds/<breed-id>.md`, `content/de/articles/<german-slug>.md` (front matter `en:` names the English article it matches) and `content/de/about.md`. Links can use the English URLs (`/breeds/beagle/`, `/calculators/crate-size/?breed=…`): the build rewrites them to the German pages.
- **Airline notes:** `content/de/airlines.json` translates the carrier sizes and notes in `content/airlines.json`. The build fails if a new English note has no German entry.
- **Comparison tool:** the German labels for `index.html` are in `tools/site/de/tool.js`. If you change English text in `index.html`, the build stops and names the text that needs a German counterpart. German breed names and URLs for the scripts are written to `js/i18n-de.js`; `js/app.js`, `js/calc.js` and `js/finder.js` switch to German when it's loaded.
- **When you change an English breed text,** update the German one in `content/de/breeds/` too, because nothing checks that they stay in step.
